# 保养提醒状态流转说明

## 设计原则

- **一模具 + 一计划 = 一条记录**：每个模具的每个保养计划在 `maintenance_reminders` 表中仅保留一条记录，通过在同一记录上「滚动周期」进入下一轮提醒。

## 状态定义

| 状态码 | 名称   | 说明 |
|--------|--------|------|
| 1 | 待处理 | 本周期尚未发送提醒，或刚滚动到下一周期。定时任务会扫描并可能发送。 |
| 2 | 已提醒 | 本周期已向管理员发送过提醒，等待执行保养或用户操作。定时任务在满足条件时可能再次发送。 |
| 3 | 已完成 | 当前实现中不写入；保留用于历史数据或扩展。 |
| 4 | 已忽略 | 用户对本条提醒点击「忽略」，定时任务将不再处理该记录。 |

> 说明：状态 2 在界面与 SQL 中可展示为「已提醒」或「已发送」，语义均为本周期已向管理员发送过提醒。

## 状态流转图

```
                    ┌─────────────────────────────────────────┐
                    │                                         │
                    ▼                                         │
              ┌──────────┐    定时/手动发送      ┌──────────┐  │
              │ 待处理(1) │ ──────────────────►  │ 已提醒(2) │  │
              └──────────┘                      └─────┬────┘  │
                    ▲                                  │       │
                    │                                  │       │
                    │        录入保养记录               │       │
                    │    （同一条记录滚动下一周期）      │       │
                    └──────────────────────────────────┘       │
                                                                 │
              待处理(1) 或 已提醒(2)  ──── 用户点击「忽略」 ────► 已忽略(4)
                                                                 │
                                                                 │
                                                    （定时任务跳过，不再处理）
```

## 触发说明

| 触发动作 | 状态变化 | 备注 |
|----------|----------|------|
| 新建保养计划 | - → 待处理(1) | 为该计划创建首条提醒记录 |
| 定时任务发送 / 手动「发送提醒」 | 待处理(1) → 已提醒(2) | 更新 `sent_at`、`reminder_count` |
| 录入保养记录（同模具+同计划） | 已提醒(2) → 待处理(1) | 同一条记录：顺延 `next_due_date`/`next_due_cycles`，清空 `sent_at`、`reminder_count` |
| 用户点击「忽略」 | 待处理(1) 或 已提醒(2) → 已忽略(4) | 仅 1、2 可忽略；3、4 不可再操作 |

## 定时任务行为

- 每日 03:00 扫描所有提醒记录。
- **只处理** 状态为 待处理(1) 或 已提醒(2) 的记录（即 `status IN (1, 2)`）。
- **跳过** 已完成(3)、已忽略(4)。
- 满足「时间临近」或「模次临近」阈值时发送站内/WebSocket 提醒，并将状态置为 已提醒(2)。
